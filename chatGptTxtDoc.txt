The key design principle should be:

MongoDB + Blockchain = source of truth; AI = assistant that explains/retrieves that information.

Start with MongoDB before blockchain.

 ├── targetAmount
 └── currentAmount

Donation
 ├── _id

Expenditure
 ├── _id
 ├── ngoId
 ├── campaignId
 ├── amount

Document

Don't start with 20+ collections. Keep the first version manageable.

Phase 5 — Implement blockchain

Now introduce Solidity.

Create a smart contract for the transactions that need immutable verification.

For example:

recordDonation()
recordExpenditure()
getDonation()
getExpenditure()
verifyTransaction()

The simplified flow becomes:

Donor
 ↓
React
 ↓
Express
 ↓
Smart Contract
 ↓
Ethereum
 ↓
Transaction Hash
 ↓
MongoDB

Store the transactionHash in MongoDB so your application can easily associate the application record with the blockchain record.

Important

Don't store everything on blockchain.

For example, don't put:

name
email
password
PDF
large description

on-chain.

Instead:

MongoDB
→ application data

Blockchain
→ immutable transaction information

IPFS
→ supporting documents

Phase 8 — Add your AI feature

Only after your normal application works should you add AI.

Your feature:

AI-powered natural-language assistant

Example:

"How was my donation used?"

The architecture should be:

User question
      ↓
React
      ↓
Express API
      ↓
Identify user
      ↓
Retrieve authorized data
      ↓
MongoDB + Blockchain
      ↓
Relevant donation/expenditure records
      ↓
LLM
      ↓
Natural-language response
      ↓
React
Example

User asks:

"How was my donation used?"

Your backend retrieves:

Donation:
₹10,000

Campaign:
Education Support

Expenses:
Books - ₹4,000
Supplies - ₹3,000
Transport - ₹2,000
Other - ₹1,000

Then AI generates a readable response.

🚨 Very important AI security rule

Don't simply send:

User question
     ↓
LLM
     ↓
Answer

Instead:

User
 ↓
Question
 ↓
Backend authentication
 ↓
Check authorization
 ↓
Retrieve verified records
 ↓
Give only authorized data to AI
 ↓
LLM
 ↓
Answer

For example, Donor A shouldn't be able to ask:

"Show me all transactions of Donor B."

The backend must restrict the data before the AI sees it.

This is a great point to discuss during your project viva.

Phase 9 — Make the AI more reliable

Initially, you can implement:

    ↓

    ↓

RAG version
Question
   ↓

   ↓

   ↓

   ↓

   ↓

   ↓

For your project, MongoDB Atlas Vector Search is a logical choice because you're already using MongoDB.

But don't make RAG mandatory from day one.

AI

Test questions such as:

How much did I donate?

How was my donation used?

How much was spent on education?

Which campaign did I support?

Show me my recent donations.

Also test questions where the answer doesn't exist.

Your AI should respond:

"I couldn't find verified information for that request."

rather than inventing an answer.
